# 按学号批量调整群组

入口：开发者后台 → 插件 → 身份插件 → 批量调整群组。
只有原生 `admin`（本站开发者）可访问页面、明细、CSV、执行和撤销；受限管理员是原生 moderator，不获得此能力。

默认“毕业转为校友”读取现有 ISBF-Alumni 的生效校友组，不推算毕业年份。可选要移除的学生／年级群组；未选群组保留。通用模式可加入、移除手动维护的自建群组。

## 使用

1. 输入精确学号列表、单列 UTF-8 CSV（可带 `student_number`／“学号”表头），或一个按字面匹配的前缀。保留前导零。最多1500条、1MB；超限整批拒绝，不截断。
2. 核对预览的学号、账号、相关群组、拟变更及跳过原因，跨页勾选确认名单。预览30分钟有效，修改条件必须重新预览。
3. 确认后由原生任务每片段最多处理50人，并按时间预算在已提交步骤之间让出任务。页面接收 MessageBus 进度；重开批次链接可恢复，CSV区分请求与实际完成的变更。
4. 只有安全确认未执行的失败步骤允许重试，完成步骤不重放。批次原发起开发者可确认及重试，其他开发者可查看或创建撤销预览。
5. 撤销必须单独预览和确认，只反向处理已记录完成的成员变更，并恢复本批次涉及的主群组、头衔和头像群组标识。后续修改、所有者或来源状态冲突则跳过。

## 实现与安全

两张插件表保存批次、操作人、确认选择、逐账号前后快照和步骤；不保存原始上传文件。学号绑定、邀请码和账号注册记录均不修改。
群组操作使用原生 `bulk_add`／`bulk_remove`，先加入后移除，保留人数、权限、群组事件和日志；不请求欢迎通知。原生日志只关联批次编号，不写学号。
每个成员步骤单独提交，短事务锁定当前群组、用户和已有相关成员关系并重新检查。跨群组／整批不具备原子性。原生流程的外部消息、Webhook可能早于提交逃逸；中断或结果不明标为冲突，不自动重放，也不承诺撤回外部事件。
后台每5分钟恢复超过10分钟未更新的排队／执行批次；重入按批次、用户锁及持久步骤去重。发起人失去开发者权限或插件关闭时停止，权限恢复后仍需明确重试。
预览、执行限流，CSV防公式注入；进度仅向原生开发者发布计数，不含学号。撤销只影响成员与三个展示字段，不还原群组偏好、已发生事件或外部系统。

## UI依据及验证

用户2026-10-27确认：沿用原生后台布局、FormKit、表格、分页、按钮和确认框。不修改用户端主题或重新设计后台。明暗模式使用原生变量；窄屏沿用原生d-table布局与键盘表单语义。
源码/服务/权限/并发/撤销审查和隔离环境结果须与CI记录对应。Windows本机无Ruby/完整Discourse，不能把Prettier、ESLint、Stylelint当作集成验证。迁移文件先在本机准备内容；隔离CI通过原生Rails生成器生成最终版本号并保留源码产物，取回后重新提交和验证。最终生成与数据库校验结果以CI为准，本机不假称执行成功。

## 发布与回滚

CI通过并合并后先核对生效身份插件完整源码、其他插件库存和资源清单，再备份数据库、插件、配置和清单。只发布本插件兼容迁移及资源，生产只读验收，禁止用真实毕业名单测试。
代码回滚保留两张记录表及已生效成员关系；暂停未完成任务后恢复旧插件资源。需要撤销真实成员变更时，由开发者恢复新版本后重新预览和确认，不以数据库回滚覆盖后续业务。
