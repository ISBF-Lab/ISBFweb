# 简历页面反馈改进

2026-10-12（Asia/Taipei），基于用户对真实隔离预览页面的两条注释和四项功能要求。本轮只修改简历插件并更新既有独立测试副本，不写入正式环境或共享开发源码。

## 当前行为

- 最高学历与院校、LinkedIn、工作许可、视力、外语等级，以及经历中的文字和链接字段占整行。月份、短基本资料保留两列，手机全部单列。
- 输入及 textarea 示例使用较浅的局部混合色；输入内容、标签和持续显示的说明使用主文本色。
- 两个生成入口共用 FormKit 校验。缺少必填项或电话、邮箱格式无效时回到填写区；校验通过后打开原生确认弹窗。取消、Escape 和返回修改不发送生成请求，保留草稿。
- 通用提醒为“isbf-one 不核验内容的准确性与合理性，仅根据您提供的内容生成简历。请自行检查全部填写内容。”另保留“短时间内无法多次生成，请核对完整后再确认。”本轮不新增频次限制，原有服务端防滥用逻辑保留。
- 英文版另提示“请确保填写的内容为英文。isbf-one 不会自动翻译，仅将简历栏目标题切换为英文，填写内容会原样保留。”提供“返回修改”和“确认生成”。
- 确认后立即进入预览阶段，显示生成中的文字状态与“简历建议控制在一页，同时避免大面积留白。请根据预览调整内容和篇幅。”完成后展示实际 PDF 页面并开放下载。
- 英文版将栏目、基本信息标签、内容前缀和日期状态切换为英文；用户输入不会翻译、改写或删减。语言缺省为中文版，两种配色仍共享全部排版逻辑。

本轮加载状态复验发现布尔 `aria-busy` 未输出预期字符串，现已显式输出 `"true"` / `"false"`，并由实际 DOM 和原生组件测试核验。生成顺序测试使用标准 Pretender 的手动响应，先检查已进入预览、显示页数建议并隐藏旧文件，再放行响应。照片测试等待公开的读取完成回调；两个完整错误重试仅在该场景设置 240 秒上限，所有交互和断言保留，实际最终用 52.887 秒通过。没有修改业务等待上限或全局测试超时。

FormKit 在调用页面提交处理之前先进入提交状态并异步校验；原焦点可能已经变化。表单在公开 click/submit 捕获阶段记录控件，支持原生 submitter 及公开测试辅助接口的普通 submit 事件；英文入口在调用公开 `submit()` 前记录。取消后在 Ember 下一轮恢复已重新启用控件的焦点。普通返回、英文返回及手机 Escape 均经真实页面和原生断言复验，保留所有确认与原文断言。

原生 v7 的浏览器启动没有进入测试；v9 出现 `pthread_create: Resource temporarily unavailable`，同样未进入八个编辑场景。只重启该任务容器以回收退出进程，保留代码、PostgreSQL 数据和资源限制，再完成 v10。一次服务任务误用早先预览测试的日志名；已归档当前日志并给私有运行工具增加拒绝重名检查，预览四项证据以保留的 `feedback-qunit-final-v8` 为准。
