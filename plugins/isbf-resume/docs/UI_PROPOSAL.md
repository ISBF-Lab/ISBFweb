# 简历采集与生成页面设计提案

状态：历史草案，已由 [工作台简历设计 V2](UI_DESIGN_V2.md) 替代。下文保留首次字段设计的记录；其中独立三栏布局不用于后续 ISBF 接入。

## 信息结构

全局必填项只有姓名、联系电话、电子邮箱。基本信息共 19 项，七个补充模块共 39 项，总计 58 个填写项。所有字段的标签、说明、示例、类型及约束见 `resume_schema.json` 和 `FIELD_DESIGN.md`。

其他模块均可不填写。教育、工作与实习、项目与科研、校园与实践、技能证书、荣誉与奖项支持多条记录；自我评价是一个短文本框。填写一条非空经历时，要注明对应学校、单位、项目或条目名称，以免生成无法识别的经历；新增后完全留空的记录不进入简历。

## 桌面布局

已绘制桌面与手机静态草案，位于本地 `.local/resume-dev/proposal/`，用于确认新增区域的布局及状态外观。图中的 PDF 缩略图为排版示意，不是功能验收证据。

```text
简历生成器                                      保存草稿 / 导入内容
填写经历，选择模板，导出简历

模块导航        内容填写区                         简历预览区
基本信息        姓名 *                            蓝金 / 蓝灰
教育背景        [填写框]                          A4 简历预览
工作与实习      姓名的填写说明                     当前页数 / 生成状态
项目与科研      联系电话 *                         生成预览
校园与实践      [填写框]                          下载 DOCX / 下载 PDF
技能与证书      投递海外岗位建议加区号
荣誉与奖项      电子邮箱 *
自我评价        [填写框]
                推荐学校邮箱/专业稳定的商业邮箱
                求职意向、现居城市、期望城市等
                按需展开的补充资料
```

基本信息先展示三个必填项，以及求职意向、现居城市、期望城市、最高学历与院校和证件照。其他选填基本资料置于“更多基本信息”中，展开后保留完整标签与说明。不能把个人职业主页、签证许可或体貌字段改为必填。

每个填写框上方有明确标签和必填/选填标记，下方持续显示说明；有示例的字段另提供 placeholder。用户开始输入后，说明仍可见。日期及勾选项也有说明，通过 `aria-describedby` 与原生控件关联。

多条经历通过“添加一条”“删除本条”管理，已有内容不因切换模块或模板丢失。用户输入顺序就是导出顺序，说明建议最近经历放在前面，程序不推测经历重要程度或重新组织事实。

## 手机布局

提案尺寸以可读性为准：普通输入框约 44 px 高，标签约 14 px，常驻说明约 13–14 px；字段间留 20–24 px，内容组之间留 32 px。桌面约 1200 px 及以上采用三栏，中等视口把预览放到填写区下方，手机采用单列。以上均为新增简历区域待确认的尺寸，不覆盖已有认证组件的尺寸与样式。

单列排列填写区、模板选择、预览和下载。模块导航改为内容内跳转或折叠分组，不把桌面两栏压缩到窄屏。说明不依赖 hover；错误信息应在对应字段附近显示，生成反馈用可访问的状态区域。证件照、长链接及多条经历需在 390 px 视口核对。

## 交互与数据

- 用户点击生成后，对必填项、日期、图片和链接执行前后端一致验证。错误保留已输入内容，定位到具体字段。
- 空字段、空照片和空模块不在导出文件中占位。仅有联系方式的简历也可以生成，不强迫填写工作经历。
- 完全机械填充，保留原文，不通过外部 API 理解任意文件或改写内容。
- 内容超过一页时显示实际页数并正常分页。PDF 由同一 DOCX 本地转换，用户看到生成后的实际 PDF 再下载两个文件。
- 切换模板只更改颜色。修改字段后标记旧导出已过期，再次生成才可下载新版本。
- 草稿保存应由用户主动触发；真实简历、照片和下载文件不提交代码仓库，不用于公共示例。

## ISBF 设计来源与复用边界

服务器 `AGENTS.md` 的新 `Frontend Design Consistency` 要求缺少匹配 Approved 规则时先提出方案并等待人工确认。

现有 A08/C02 只批准工作台入口网格，可用于未来入口外观；A01/C04 只批准既有接管路由的页面壳，不能据此批准新路由或内层表单。C08 的认证输入与表单尺寸只批准认证流程，不能移植为简历表单样式；C07 未建立公共弹窗外观，当前提案采用页面内反馈，不新增弹窗。

工程实现拟使用公开 FormKit 与 UI kit、BEM 和可翻译字符串，沿用适用的 ISBF 基础 tokens。新区域仍需确认：桌面填写区与预览区的布局、输入与说明的左对齐形式、字段间距、选填资料折叠方式、上传与预览外形，以及 invalid/loading/disabled/empty 状态。不能先用认证居中表单或 Discourse 默认外观填补这些缺口。

确认后才接入 ISBF 内层页面；正式发布仍需隔离测试页面验收、此次版本明确上线授权和新鲜备份。
