## 定位接口

款式表新增 `scale`、`offset_x`、`offset_y` 和 `calibration_confirmed`。
前三项是头像图像内容区域的百分比：大小默认 120，范围 50～300；两个偏移默认 0，
范围 −100～100。头像内容直径为 `A`，图片边长为 `A × scale / 100`，
图片中心相对头像中心移动 `A × (offset_x, offset_y) / 100`。

共享 `avatar-frame-position` modifier 从实际 `img.avatar` 测量尺寸，减去边框和内边距，
以实际位置定位叠层。它在尺寸变化和头像加载时更新，销毁时断开 observer。
预览清除继承的 3px margin；主页保留原有 4px 白边。所有挂载点复用相同算法，
不按路由、款式名称或 UUID 写 CSS 补丁。点击、flair 层级及减少动画的静态回退保持原有行为。

## 上传和确认

上传入口维持管理员权限及站点上传限流。解析 PNG 后，使用核心的 ImageMagick
沙盒检查真实透明像素，拒绝完全不透明的 PNG，包括只在调色板声明但没有实际使用的透明色。
288px 灰度分析图只在临时文件中用于定位建议，遵循现有 coder、文件访问和资源限制，
不修改上传原图。默认图像的 alpha 沿 360 个方向取透明内缘，剔除离群点后拟合圆：
至少 85% 方向匹配、缺口不超过 35°，且圆心和直径在合理范围内才给出建议。
复杂、非闭合和空画布不产生建议，仍可人工校准。

后台在已有上传字段内增加 144px/48px 叠加预览，三项数字输入及恢复默认操作按单列排列。
建议需点击采用；不会自动替管理员确认。调整数字或替换图片会清除前端确认。
服务端只接受 `confirm_calibration`，不会把直接提交的 `calibration_confirmed` 当作确认。
模型在图片或定位变更时清除持久确认，启用款式必须已确认；停用草稿允许未确认保存。
迁移为原有记录保留确认状态，新记录默认未确认，不重新执行初次安装的 SeedFu 导入。

## 实施审阅

| 检查范围 | 处理方式 |
| --- | --- |
| 服务与控制器 | SaveFrame 负责合同、定位赋值和保存；上传分析在专用对象内；控制器只处理响应 |
| 步骤与失败处理 | 管理员 policy 先执行；只读 defaults 保留省略参数；model 步骤验证后在事务内保存和记日志 |
| 合同与模型 | 大小和偏移在两层校验；确认状态与当前图片、定位变更绑定；已有元数据编辑不重置校准 |
| 权限与输入 | 现有管理员 Guardian、POST/PUT、CSRF 和上传限流保留；纯数字定位，无 HTML 或外部命令插值 |
| 图片处理 | 使用核心 ImageMagick 文件沙盒，不放宽 stdio/GRAY coder 策略；处理固定 288px 临时 mask |
| 数据与副作用 | 不修改授予、CSV、用户佩戴或原始上传；保存后刷新目录缓存，工作人员日志与保存同事务 |
| 并发与幂等 | 没有新增批量写入或外部调用；重复保存确认不新增授予或通知；没有不必要的分布式锁 |
| 序列化与 API | 现有 FrameSerializer 增加数字及确认字段；Pair 显式暴露建议；HTTP 状态和错误接口保留 |
| 前端与样式 | FormKit/UI kit、翻译和 BEM；共享定位、完整装饰、不截获点击；校准布局仅限已确认区域 |
| 迁移 | Rails generator 时间戳；事务内新增带默认值列，旧数据确认保留，新数据默认未确认；无应用代码或重建数据 |
