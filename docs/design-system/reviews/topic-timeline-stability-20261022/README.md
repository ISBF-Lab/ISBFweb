# 时间轴浮层标记稳定性修复

用户提供了2026-10-22电脑和手机截图：点击阅读进度后，时间轴退回占满视口宽度的底部面板。
本次恢复此前确认的右侧窄幅毛玻璃布局，不新增视觉规则；日期在左、轨道在右，
12px页边距、60%主题背景、24px模糊和手机底部安全区沿用原方案。

## 原因与修复

旧实现用`classList.add()`向原生导航添加`isbf-topic-reading`。
Ember更新展开状态时会重写该元素的`class`，导致浮层选择器失配；
原生底部面板是固定定位，父导航可以保持零高度，`ResizeObserver`无法保证触发补回类名。

[修复前的真实客户端复现](browser-before.json)在两端均确认：导航`position: static`、高度0，
内部容器变成`position: fixed`，分别铺满1440px和390px；标题被隐藏、玻璃模糊消失。
线上字段摘要与工作区一致，浮层SCSS仍在，问题不是该样式被后来发布删除。

修复通过模板始终渲染的`.isbf-topic-reading__heading`识别归属，统一使用
`.topic-navigation:has(.isbf-topic-reading__heading)`应用布局和外部点击排除。
普通话题的网格及桌面隐藏规则同步调整；删除脚本添加或清除导航/帖子布局标记的逻辑。
保留尺寸观察用于读取原生进度是否可用，不再用它修复样式类。

普通话题与分组回复复用同一个阅读组件，原生导航、状态和讨论组索引保持。
固定60px页头的测量规则保持；没有添加第二套滚动校正或修改核心、公开API、数据库结构。
