## 状态与接口

`academy_password_setup_pending`是服务端管理的布尔用户自定义字段，仅在新建真实、非暂存、非匿名且无密码账号时写入；不登记为用户可编辑字段，不回填历史账号，不新增数据库迁移。当前用户序列化仅在本人有权限、可使用本地登录且尚无密码时返回待提醒状态。停用、模拟登录及未获准访问论坛的账号没有资格。

首页路径为`/`、`/latest`、`/hot`、`/top`、`/new`、`/unread`、`/following`和`/filter`；忽略查询参数。插件出口在页面渲染后打开弹窗，已有任务弹窗或确认框时延后。注册首先返回其他页面时，等首次进入首页再提示。

| 请求 | 行为 | 结果 |
| --- | --- | --- |
| PUT `/academy-roles/password-setup.json` | 仅当前用户；`password`、`password_confirmation`；复用现有密码验证与保存 | 200：`success: true`、`no_password: false`、`academy_password_setup_pending: false` |
| DELETE 同路径 | 幂等消耗当前用户的提醒资格，不设置密码 | 204，无响应正文 |

鉴权、插件开关、本地登录、CSRF及限流在服务器执行；API凭据及模拟登录不得直接设置密码。设置和跳过均先锁定当前用户行，再在同一事务里重新读取资格。已有密码或已跳过的设密请求返回409，不能覆盖密码。校验失败返回422，不消耗提醒资格、不撤销当前会话。超出核心凭据管理使用的五分钟新账号信任窗口、未经会话确认，或已启用二次验证时返回403并转入现有邮件验证流程，避免要求输入尚不存在的旧密码。

设置成功使用`User#password=`及`User#save`，保留核心哈希、密码校验和会话失效回调；同时消耗提醒、撤销相关邀请并写入密码变更审计。控制器重新登录当前账号，后续请求继续可用。密码和确认密码只存于FormKit瞬态草稿；本地存储及审阅日志不保存真实密码。
