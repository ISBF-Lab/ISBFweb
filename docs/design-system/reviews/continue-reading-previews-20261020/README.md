# 接着看看无标题正文预览 · 2026-10-20

用户报告话题 `/t/topic/196?sort=old` 底部仍显示内部占位标题，并确认实施修复方案。
根因是 C17 推荐条目直接使用原生 TopicLink，未采用 A12/C12 的无标题识别及正文预览。

本轮仅补齐普通话题底部“新帖与未读”和“相关话题”的无标题条目。正常标题保留原生格式；
无标题预览读取首帖 cooked 正文，复用已有清洗、200px 可见性预取、四并发队列及有界缓存。
新 `continue-reading` 变体只显示文字，纯图片使用既有“图片”，缺失正文使用“查看帖子”。
链接保留原生 linked_post_number / lastUnreadUrl，首帖预览不会把跳转位置改为首帖。
保留键盘、历史、已读无障碍文字、分类、时间、回复数和状态。无新增后端接口或迁移。

视觉沿用 C17 已确认的两行标题、既有字体/颜色、36px/30px头像及直角边框；
没有把 C12 总结链接色应用到页脚，也没有新增全局 token。
本次用户批准的是修复方案，最终视觉验收另行记录。

## 来源及验证

`before/` 保存修改前工作区快照，`source-manifest.json` 保存四个最终修改文件及摘要。
生产活动主题另做三方合并：保留线上条目原有的属性访问兼容修正，
确切发布源以部署记录为准，不整体复制工作区主题。

新增六项 QUnit 回归用例覆盖延迟正文、纯图、404、隐藏内容、交互和正常标题。
本环境无隔离 Rails 测试后端，原生 QUnit 入口未执行，不记为通过；用例编译单独记录。
离线浏览器使用完整原生核心、完整候选主题及合成 API，未使用生产作为测试后端，
没有核心模板替换。旧夹具主题语言数据需在已初始化的 js.theme_translations 节点补齐；
早期夹具失败保存在 attempts/，不是产品请求失败。

定向 lint、组件/测试编译、完整样式与两套配色、完整候选主题和浏览器检查分别记录。
单个无网络工具串行运行，按每次可用内存及 cgroup 剩额减至少512MiB设置预算，
相同内存/总交换上限、0.5CPU、192进程；完整预览论坛保持停止。
实际预算、峰值、退出与清理见 tool-executions.jsonl 及部署目录预算记录。
