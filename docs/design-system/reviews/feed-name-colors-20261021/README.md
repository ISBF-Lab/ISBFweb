## 颜色问题与局部修复

原始[诊断](../feed-link-colors-20261020/README.md)指出核心 `a:visited` 等状态规则的优先级高于主题单类颜色规则。项目已有的[Safari截图](../landscape-image-gap-20261020/reported-gap.png)进一步显示姓名与账号同色、标题与时间同色，分别对应相同的用户/话题href。卡片生成裸话题地址，阅读路由可在跳转完成前补上 `?sort=old`；进入话题不保证原始裸地址被记录为已访问。

在卡片的作者、账号、时间、标题四个链接本身设置 `--d-link-color`，让已有状态规则读取正确颜色。正文链接、全局链接状态、焦点及阅读记录不变。浏览器出于隐私限制会隐藏访问状态，不能仅凭 `getComputedStyle()` 或脚本查询认定Safari访问历史颜色已验收。

标题字号与24px间距只在 `.isbf-feed-card` 下生效，避免影响复用标题类的详情。标题存在时移除首段/首图重复顶部间距；无标题卡片沿用原布局。

## 权限与数据契约

- 项目开发者为原始 `User[:admin]`，管理员为原始 `User[:moderator]`。受限管理员的有效管理标记可为false，姓名颜色权限独立判断，不恢复管理权限。
- `academy_name_color_enabled` 为默认关闭的布尔自定义字段，`academy_name_color` 保存可空六位 `#rrggbb`。开发者输入三/六位十六进制均规范化，拒绝任意CSS；自选色跨明暗模式不变。关闭佩戴保留色号，清空色号恢复主题蓝，不改变佩戴开关。
- 通过既有 `PUT /u/:username.json` 保存 `custom_fields`，合并保留其他字段，无数据库迁移。服务端限制本人操作，非开发者不能修改自选色，普通账号不能启用佩戴。
- 私有 `academy_name_color_preferences` 及两个能力字段只向本人序列化。公开作者字段 `academy_display_name_color` 为null、`theme`或标准色号；仅信息流使用它。列表批量预载，匿名影子/池账号不继承本人的角色或颜色。
- 前端草稿只用于局部预览；成功响应才更新当前用户的有效显示色，使已经加载的本人卡片同步。请求失败保留原显示；其他浏览者下次加载获得保存结果。角色变化按当前身份重新判断，旧色号不阻止无关资料保存。
- 身份降级后的保存会同步撤销颜色控件能力，但不会把普通账号的只读默认值写回旧色号。服务端按规范化后的颜色/布尔值判断选择是否改变，允许旧表单原样重发既有选择；新启用佩戴或更换颜色仍按当前角色拒绝。
