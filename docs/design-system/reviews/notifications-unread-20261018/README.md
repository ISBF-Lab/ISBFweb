# 通知未读提示 · 2026-10-18

用户已确认实施方案：电脑及手机显示主题强调色角标；默认数字，超过99显示99+，
无未读时隐藏。用户在通知页菜单切换数字/圆点，偏好保存到账号。
所有已有站内通知计入；默认显示全部，“只看未读”开关放在右上角三点菜单内。
打开栏目、切换标签和展开动作组不标已读；具体通知及全部已读沿用原生操作。

## 设计来源和范围

复用A01导航、A05分组通知、C05标签、C06通知菜单和C13条目；
历史参考附件及其摘要保持不变。新规则仅作用于通知入口和当前用户的分组通知页。
设计方向已由用户确认；实际来源以本目录source manifest为准，最终视觉待用户核验。

- 角标使用accent/accent-contrast、font-xs、weight-bold、radius-pill；
  数字最小宽高space-5、水平内距space-1，圆点宽高space-2。
- 动作的未读点复用space-2和accent，附有翻译的屏幕阅读器文字；
  与动作文字用flex垂直居中，主题大标题不放点。
- 两项标签及既有通知菜单保留；显示偏好以两项互斥按钮加入菜单。
- 菜单内筛选行复用space-3、font-sm及UI kit开关，局部开关24×48px，
  点击区域高度44px。该组合不升级为全站控件标准。
- 侧栏的折叠规则继续隐藏文字，但排除铃铛和角标，避免未读提示一起消失。

## 行为与接口

主题共享服务汇总`grouped_unread_notifications`，保留原生计数上限，
超过99只表达99+。不使用受`seen_notification_id`影响的未看过计数；
合并点赞的多名参与者仍共享一条原生通知ID。
共享服务监听已有用户私有通知通道及本地点击事件，更新列表中的已读状态；
重查已加载页时保留分组key和独立展开状态，刷新详情游标，丢弃过期响应。

`isbf_notification_badge_style`为私有用户自定义字段，值为`number|dot`，
通过原生用户更新接口保存，仅在当前用户序列化中额外提供默认值；无需迁移。
保存失败保留旧外观并提供重试。其他设备重新加载账号时使用保存值。

分组列表和详情接口接受`filter=all|unread`，默认all；先筛选原生记录，
再分组、选择代表条目和分页。详情URL携带tab/filter，签名游标绑定二者；
旧游标仅兼容all模式。原有收件人及帖子可见性检查继续生效。
全部已读请求期间若收到新通知状态，客户端不会在响应到达后盲目清零。
