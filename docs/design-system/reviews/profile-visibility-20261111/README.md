# 个人资料分项可见性（2026-11-11）

用户要求优化“隐藏我的公开个人资料”，让用户自行选择哪些部分公开，并确认了范围：
简介信息、总结页、活动页三个分项；每项只有公开／隐藏两档；保留原总开关作为“全部隐藏”；
被隐藏的部分对本人及管理人员（开发者与管理员）仍可见。用户同时要求界面遵循本站 UI 风格，
别人查看被隐藏用户时的界面也要保持美观。徽章未列入可控分项，保持公开。

功能先在核心实现；用户看过后要求不改核心，改为独立插件 `isbf-profile-visibility`。
界面与行为保持不变，核心源码与表结构均已还原。

用户批准的方案文案把活动页称为“动态”。实现时改为站内标签实际使用的“活动”
（`js.user.activity_stream`），使偏好项与资料页标签同名；这一处与批准文案不同，待用户确认。

## 批准的设计与复用边界

本次只新增下列区域，不扩大完整偏好页、用户弹出卡或资料顶部的 Approved 范围。

- **偏好设置 → 个人资料的“资料可见性”区域。** 沿用已确认的偏好字段区域写法
  （[姓名颜色](../feed-name-colors-20261021/README.md)、头像框）：FormKit `Form` 与 `form.Section`、
  checkbox 及其说明文字，使用页面原有保存按钮。区域经插件出口 `user-preferences-profile` 渲染，插件样式用
  `order: -1` 把它排到表单第一项（原“隐藏我的公开个人资料”所在位置），并隐藏被取代的原单项勾选框。边框卡片、间距、标题和 checkbox 标签直接来自主题
  `profile-content.scss` 中 `.user-preferences .form-kit` 的既有规则。新增的只有分组标题与说明两处文字规则，
  限定在 `.profile-visibility` 内，取值复用 D02：标题 `font-sm`／`weight-medium`／text，说明 `font-xs`／`primary-high`／1.45；
  总开关勾选后三个分项被锁定，其标题与说明改用已有的 `--isbf-v2-muted`，不新增透明度或颜色值。
- **访客占位页（插件路由 `user.profilePrivate`，地址 `/u/:username/profile-private`）。** 改用 UI kit `DEmptyState` 的纯文字形态，直接套用主题
  `profile-content.scss` 已有的 `.empty-state` 规则（D03：左对齐、标题加说明、无背景与插画），没有新增样式值。
  总开关隐藏时标题为“个人资料已隐藏”，正文沿用原有“此用户的公开个人资料已被隐藏。”；
  总结与活动都被隐藏时标题为“暂无公开内容”，正文为“此用户未公开总结和活动。”
- **空的一级导航。** 资料页一级导航没有任何标签时不再显示胶囊轨道。由主题 `ProfileNavigation`
  给导航加 `is-empty` 状态类，样式只有 `display: none`；有标签时的 A11 导航外观不变。
- **资料顶部（A11）样式未改。** 简介被隐藏时，顶部与未填写简介的用户相同；封面使用既有无封面状态。
  总开关隐藏的资料原先被核心强制成没有设计的“收起”头部，看过截图后用户要求调整：现在它使用 A11 已批准的
  展开头部（封面、大头像、姓名、私信／聊天按钮）；插件样式隐藏没有内容的详情面板并去掉其内层分隔线
  （`.container.profile-hidden … .details { border-bottom: 0 }`、`.secondary { display: none }`），主题不改。没有新增颜色、尺寸或间距。
- **总结标签。** 核心导航总会输出“总结”标签；总结被隐藏时插件给页面加 `isbf-profile-summary-hidden` 状态类，
  插件样式隐藏该标签（含侧栏用户导航）。主题导航据此只按可见标签判断轨道是否为空。

## 行为

| 状态 | 其他用户与未登录访客看到的内容 |
| --- | --- |
| 简介隐藏 | 顶部只有头像、姓名、头衔和活跃等级；头像卡片与链接预览同样不含简介、所在地、网站、精选话题 |
| 总结隐藏 | 没有“总结”标签，默认进入“活动”；头像卡片不显示阅读时长 |
| 活动隐藏 | 没有“活动”标签；总结页不再出现指向活动的链接 |
| 总结与活动都隐藏 | 占位页；有徽章时仍显示“徽章”标签 |
| 总开关隐藏 | 占位页；不显示导航轨道 |

直接打开被隐藏标签页的链接会回退到仍然公开的标签页；两者都隐藏时进入占位页。
总开关勾选后三个分项置灰并保留原值。

隐藏由服务端执行：资料与头像卡片数据、总结接口、活动列表及其 RSS、
投票／已解决／回应列表、用户链接预览和 MCP 用户工具都按同一规则判断，前端只负责标签与跳转。
用户目录 `/u` 的统计、搜索结果和话题内的帖子不受影响，与原总开关一致；
校友资料与简历分享沿用各自的可见性规则。

## 顺带修复

- 查看被总开关隐藏的资料时，活跃等级显示为“LV[missing %{level} value]”：隐藏资料不下发等级。
  学院角色插件的资料顶部连接器现在只在等级存在时渲染，LV0 照常显示。
- “某用户投过票的话题”列表（`/topics/voted-by/:username`）原先不检查资料是否隐藏，现与活动页一致。
- 总结数据按查看者缓存一小时。缓存键加入“能否查看活动”，用户隐藏活动后别人看到的总结立即更新。
