# 帖子互动按钮回弹与数字滚动

用户确认信息流卡片、普通话题主帖、根评论和子回复的点赞／引用／评论／收藏统一增加
PulseHeart动效，保留当前图标、尺寸、配色、排列及原有业务状态。已同步独立开发站，
生产未发布，最终外观待用户验收。用户随后根据截图（保留在本地验证记录中）确认去掉鼠标悬停底色，保留图标变色，并明确授权完成PR和生产发布。

## 来源与实现

设计来源为本次用户提供的PulseHeart JavaScript＋CSS及后续确认，见[范围记录](reference.json)。
静态外观复用A02/A04/C09/C16和2026-10-21五项操作栏间距，不新增全站视觉token。
实现位于活动主题，使用Ember/Glimmer、DButton和现有图标，无新增npm依赖。
信息流的DButton图标局部映射为按钮当前色；列表收藏的静态状态保留既有
`.topic-list .d-icon-bookmark`局部覆盖，深色下可与文字色不同。验证同时使用原始按钮DOM
作SVG颜色对照，避免把既有覆盖误判为动效引起的颜色变化。
当前运行样式的点赞列存在约4px的既有偏移。本次按用户选择保留现状，分组回复验证将数字
还原为改造前的原始文本DOM，与新数字组件逐项量测图标位置；不把历史等距规范误当作本次新增的间距修复。

按压0.97，主过程560ms，40%处缩至0.3，回弹系数1.7，按钮视觉轻缩3%，数字滚动350ms。
单个字符变化只滚动该位，进位／长度变化滚动整组，零值按原规则隐藏；详情整数和信息流
compact格式分别保留。动画使用transform，不改变操作栏布局尺寸。
退位滚动期间由动画数字撑开原数字所需宽度，避免两位数退到一位数时裁掉旧数字。

点击立即反馈，业务动作同时执行。动画不增减计数、不设置选中状态，也不等待动效结束才请求。
详情点赞继续沿用原生模型的乐观更新／错误处理；信息流沿用请求成功后更新。
引用和评论保持一次性动作，不生成计数或选中状态。原生赞数弹层、收藏提醒、权限和回复目标保留。
重复按压替换旧动画；取消触摸、失焦、实时切换减少动态效果及销毁会释放资源。
键盘、初始化及外部同步直接显示真实值，装饰数字层对读屏器隐藏。

悬停修订仅作用于四类动作及点赞数字入口。既有hover规则读取局部透明变量；原生点赞组悬停时，两个按钮都保持透明。点赞悬停显式使用既有love粉红色，其他动作使用accent；移开恢复原状态色。本人收到点赞的心形入口也提供同样的粉色悬停提示，点击仍打开原生人数菜单；禁用按钮保留原状态。点击范围和排列保持，键盘焦点沿用既有提示；三点菜单和其他按钮不变。

## 核心扩展点

`PostMenuLikeButton @animate=false`直接调用原有动作，关闭其400ms默认延迟／动画；
未指定参数的调用继续使用原行为。新增可选`:count`块，将原始计数向`LikedUsersList`
传递并渲染在原有按钮内，未提供时仍输出原数字。该块不替换赞数按钮或菜单处理。
后端请求协议、数据库结构、主题设置及其他按钮不改动。

真实流程还发现主帖收藏的既有调用问题：经典Topic属性缺少显式跟踪，导致图标不随状态刷新；
取消收藏使用DELETE，而当前既有路由要求PUT。本次通过响应式读取及匹配既有PUT路由修复，
并补充选中语义和创建／取消的回归测试，没有新增后端API。
