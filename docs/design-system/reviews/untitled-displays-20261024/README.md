# 无标题帖子展示补齐 · 2026-10-24

用户报告 `/u/devadmin/activity/topics` 在发布后显示内部占位标题，并选择以正文摘要替代，覆盖全部前台入口；同时授权校验后提交PR、合并和生产发布。

## 原因与本次边界

“发布的话题”和“已读”走 `UserTopicListRoute`、`BasicTopicList` 和 `TopicLink`，不经过个人全部动态的 `UserStream`。以前的公开活动预览修复无法覆盖该路径。搜索高亮、书签、草稿、匿名列表、资料精选话题、邀请、帖子信息及分享另有直接消费标题的入口。

本次只替换系统生成的 `校园动态 [isbf-untitled:UUID]`。有标题的条目保留原格式与富文本处理；普通方括号和正文中的文字不作为占位标题清理。采用C12已接受的正文提取与最多300字符规则，紧凑话题链接沿用两行纯文字。字体、颜色、间距、表格、卡片、导航、操作、排序、分页及原始目标不变，不增加缩略图。纯图片使用现有“图片”翻译，无内容和失败使用现有“查看帖子”。

新增 `topic-display-title` value transformer 只改变展示文本，默认返回原值；`topic-link-title`出口位于原链接内部，不复制链接、不覆盖属性或未读目标。主题识别占位标题，复用已授权正文、摘要或搜索blurb；公开话题链接缺摘要时才使用现有4并发、50项缓存的按需加载器。草稿、私信及受限分类不接入该公开加载器。原始数据库标题、API字段和草稿序列化不改；无标题编辑器显示空值，清空时保留原占位标识。

个人资料、书签、草稿、搜索及信息弹窗仅批准本次文字替换，不升级为公开信息流或扩大整页Approved范围。A12/C12的旧参考和迁移捕获清单保留。工作区活动主题通过增量同步开发站；PR以独立工作树承载本次差量，不将GitHub main覆盖到捕获运行源码。

## 译文标题优先级

审查发现：序列化的原始 `title` 仍可能是占位标识，而已选择语言的标题位于 `fancy_title`，通过 `fancy_title_localized` 标记。展示时优先保留可用译文及其原生富文本格式；搜索高亮、书签、浏览器标题、分享和活动纯文字入口同样遵守此规则。仅在译文缺失或为空时继续使用正文摘要。有译文的链接不订阅正文加载；切换语言或异步收到译文时，链接、分享和活动缓存会更新。原始标题、未读目标及书签的具体楼层均保留。新增回归及当前验证见[译文修订验证](localization-verification.json)。

## 验证与发布

首版定向lint、原生主题编译及弹窗规范检查通过。主题15个用例63条断言、核心7个用例10条断言、21项手机390px和电脑1440px实际页面检查全部通过；明暗截图保留在工作区，不包含在公开PR。首版结果及精确提交的CI见[验证记录](verification.json)。初次筛选格式错误执行0项有效测试；随后回归发现并修正书签只读计算属性和编辑代理访问错误，另修正原生链接slug和分类标题的测试预期。失败尝试不计为通过。

本次测试仅连接独立开发站及合成Pretender夹具。生产发布须在精确PR提交的CI和审查通过后执行，以当时实时源码和数据库主题为基线增量合并，核对完整运行库存、受影响字段与HTTPS资源；记录定向恢复与临时工具清理。生产现有31个受控核心文件均与工作区基线一致；公共SCSS包含独立增量，候选只合并新增的两行标题规则，更新3项、增加4项主题字段，其余259项及6个设置保留。
