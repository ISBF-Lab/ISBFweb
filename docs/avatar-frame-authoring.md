# 头像框制作、上传与授予

适用于论坛 `discourse-avatar-frames` 适配版 0.4.0。安装和发布记录见
[头像框部署记录](avatar-frames-deployment-20261010.md) 和 [校准增量发布](avatar-frame-calibration-production-20261011.md)。

## 制作素材

- 使用 288×288 像素的正方形透明画布，不包含用户头像和背景。
- 中心参考圆直径约 240 像素，中心为 `(144, 144)`，外接方形左上角为
  `(24, 24)`。头像框显示为头像尺寸的 120%，参考圆对应实际头像的位置。
  导出前隐藏参考圆。
- 中央留透明，装饰主要分布在圆周，避免遮挡脸部。缩小到 32～48 像素检查清晰度。
- 静态款导出透明 PNG；动态款导出 APNG，扩展名仍为 `.png`。
- 系统保留上传的动画原图，自动从默认图像生成静态版本。首页、账号菜单、选择预览
  和系统减少动画模式使用静态版本，帖子和个人资料可以显示动画。
- 图片须为正方形且包含真实透明像素，完全不透明的图片会被拒绝。PNG 调色板的透明色
  也支持，但仅声明未实际使用的透明色不够。大小和像素数遵循站点图片上传限制。
- 动画播放全过程保持同一头像圆心和定位区域；允许 APNG 使用不同大小的增量帧。

制作时可以使用 [头像定位参考 SVG](downloads/avatar-frame-guide.svg)，导出前隐藏或删除
`guides` 辅助线组。288×288 不能单独保证对齐，上传后要检查叠加预览。
可靠闭合圆环可能出现“使用建议位置”；非闭合、复杂装饰可以人工调整，
系统不会按照挂件或嫩芽的外接框自动居中。实现与定位参数见
[校准说明](avatar-frame-calibration-20261011.md)，排查依据见
[对齐排查](avatar-frame-alignment-20261011.md)。

## 后台上传

管理员打开 `/admin/plugins/discourse-avatar-frames/frames`，点击“新建头像框”，
填写名称、说明、显示顺序，上传 PNG。手机端先打开列表右上角的更多菜单，再选择“新建头像框”。

上传后查看 144px 和 48px 两种叠加效果。默认大小为 120%，必要时调整“大小”、
“左右位置”和“上下位置”，也可以恢复默认位置或使用圆环识别的建议。
位置为正数时向右或向下移动，位置为负数时向左或向上移动。
大小支持 50%～300%，两个方向的偏移各支持 −100%～100%，均按头像图像尺寸计算。
确认“我已检查两种预览并确认对齐”后保存。替换图片或调整定位后需重新确认。
未确认的款式可以停用保存为草稿，确认后才能启用供用户选择。

定位参数随款式保存，设置预览、个人主页、帖子和主题头像使用同一组参数。
头像框缩放不计入个人主页的 4px 白边，动态和静态版本保持相同位置；原图不会
为了校准被重新编码或裁剪。

新款默认“授予后可用”；改为“所有人可用”后，无须授予即可选择。
停用款式会隐藏展示和选项，但保留授予记录；重新启用后恢复。
后台上传、编辑、授予、撤销和导入仅限管理员，版主没有这些权限。

新增款式无须修改代码、登记 ID 或重新构建论坛。图片通过 Discourse 上传存储保存，
随站点上传备份维护。隐藏的旧 `avatar_frames_config` 仅用于初次导入原有名称和旧版回退。

## 单人授予与撤销

在“授予后可用”的款式上点击“管理授予”，选择用户并点击“授予头像框”。
授予永久有效，首次授予发送站内通知，链接到个人资料设置。
不会自动替用户佩戴。用户在 `/my/preferences/profile` 的下拉列表中选择并保存变更。

重复授予同一款式不会重复建立记录或发送通知。管理员可在持有用户列表中撤销，
若用户正佩戴该款式，同时移除其选择。修改为公开款式后，撤销持有记录不影响公开使用。

## CSV 批量授予

先进入目标款式的“管理授予”，选择 CSV，再点击“导入并授予”。

文件要求：UTF-8 编码（支持 BOM），最多 50,000 条非空记录，第一列为用户名或邮箱。
表头可省略，也可以使用英文 `username` 或 `email`。例如：

```csv
username
alice
bob@example.com
carol
```

同一人以用户名和邮箱出现会合并。空行、重复用户跳过；无法匹配和匿名账号不授予。
导入只追加持有记录，保留已有授予。后台每批处理 200 人，页面显示匹配、新授予、
已拥有、未匹配、失败及处理进度，并列出最多 100 条未匹配或失败记录。

任务重试不会重复授予或重复通知。完成后重新导入同一个 CSV 时，已有用户计入
“已拥有”。离开页面后任务仍继续，可以重新打开该款式查看最近 20 次导入记录。

## 开发与维护

数据库使用独立的款式、授予和导入表。用户当前选择仍使用 `avatar_frame` 自定义字段，
原有六款的字符串 ID 保持不变，新款使用 UUID。服务器校验可使用款式，不能靠修改
前端选项绕过授予。图片有上传引用，避免被清理为未使用文件。

动态图片上传绕过会去掉 APNG 帧的通用图片优化。兼容图片路由为 UUID 款式保留旧主题
图片入口，默认数据库主题无需替换。

插件源码发布按固定提交存入共享目录。发布前阅读
[外部插件部署事故记录](workbench-plugins-missing-20261010.md)，保留完整插件库存、
主题及站点数据，更新资源清单、样式缓存和后台任务服务。
