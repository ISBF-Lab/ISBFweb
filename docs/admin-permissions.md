# 管理员权限开关

本论坛的“开发者”对应 Discourse `admin`，“管理员”对应 `moderator`。
同时拥有两种身份的账号按开发者处理。权限开关统一作用于所有没有开发者身份的管理员，不修改账号的身份字段、信任等级或实际用户组成员关系。

## 操作入口

开发者打开 `/admin/plugins/discourse-academy-roles/moderator-permissions`，调整开关后点击“保存权限”。保存只提交发生变化的设置，通过原生站点设置批量接口原子更新并记录管理日志。保存失败时整批回滚；成功后已有浏览器会收到站点设置刷新通知，后端的下一次请求使用新权限。

20 项权限默认关闭。全部关闭时，管理员按账号自己的信任等级、非管理用户组和内容所有权使用普通论坛功能。开发者不受这些开关限制。邀请、学号查看、角色授予和撤销、权限配置始终仅限开发者，没有相应开关。

设置需要 `academy_roles_enabled` 保持开启。关闭整个学院角色功能会恢复原生 Discourse 的权限行为。

## 权限对应表

| 开关 | 设置名 | 作用 |
| --- | --- | --- |
| 访问内部版块 | `academy_moderators_access_internal_boards` | 恢复仅向管理角色开放的内部分类及管理组消息访问；不附带校园业务分类的发布权限 |
| 查看用户管理信息 | `academy_moderators_access_user_admin` | 用户管理列表、用户详情、处罚历史；学号仍只对开发者可见 |
| 查看隐藏和已删除内容 | `academy_moderators_view_hidden_content` | 在本人有分类或消息访问权限的范围内查看隐藏、隔离、删除内容和密语 |
| 审核举报与待发布内容 | `academy_moderators_review_content` | 普通分类的举报和发布队列，不包括学习资源队列 |
| 编辑他人内容 | `academy_moderators_edit_others_content` | 编辑可见的普通帖子，包括匿名帖子；不授权学习资源主帖编辑 |
| 删除与恢复他人内容 | `academy_moderators_delete_others_content` | 普通帖子和主题删除、恢复；学习资源由专用开关控制 |
| 管理主题 | `academy_moderators_manage_topics` | 关闭、打开、归档、置顶、移动、拆分、合并等主题操作 |
| 编辑普通账号资料 | `academy_moderators_edit_users` | 普通账号的公开资料；不允许改他人邮箱或身份 |
| 封禁与解除封禁普通账号 | `academy_moderators_suspend_users` | 独立于用户详情和审核权限 |
| 禁言与解除禁言普通账号 | `academy_moderators_silence_users` | 独立于用户详情和审核权限，包括审核动作附带的解除禁言 |
| 删除普通账号 | `academy_moderators_delete_users` | 保留原生账号删除的帖子数量、时间等限制 |
| 匿名化普通账号 | `academy_moderators_anonymize_users` | 不允许处理开发者、管理员或系统账号 |
| 管理分类 | `moderators_manage_categories` | 原生分类创建和管理，仍需分类可见 |
| 管理用户组与认证成员 | `moderators_manage_groups` | 可管理的非自动用户组创建、编辑、成员和删除；不能修改自动角色组 |
| 发布校园活动 | `academy_moderators_publish_activities` | 在 `academy_activity_category` 指定分类发布活动和使用活动编辑器 |
| 使用官方身份发布 | `academy_moderators_publish_official` | 官方分类发布、官方身份和日历发布；不修改认证组成员关系 |
| 审核学习资源 | `academy_moderators_review_resources` | 学习分类的资源、课程请求队列，不附带直接发布或资源编辑权限 |
| 管理学习资源 | `academy_moderators_manage_resources` | 直接创建课程和资源、编辑、删除、恢复资源 |
| 查看他人邮箱 | `moderators_view_emails` | 独立授权邮箱；不授权 IP、单点登录数据或学号 |
| 查询匿名作者 | `academy_moderators_trace_anonymous` | 查询可见匿名帖的原作者；排队帖子还需相应审核权限 |

普通用户、已有官方认证成员和校友认证成员继续使用原有规则。管理员拥有这些非管理成员身份时，其普通成员权限也保留。管理员不能处罚或修改其他管理账号。普通用户对管理账号的防屏蔽、禁止举报等原生保护使用存储的身份判断，避免权限收紧后丢失身份保护。

自动身份组刷新也使用存储的角色字段，保留管理员的 `moderators` / `staff` 成员关系。密语查看开关仅恢复读取；创建密语仍需独立的非管理用户组授权。回复现有密语同样通过 Guardian 的创建校验。

## 权限组合

每项开关独立授权。涉及多个操作的审核动作必须同时具有所有权限，例如“同意举报并封禁”要求审核与封禁，“删除帖子并禁言”要求审核、删除与禁言。仅批准内容或驳回举报不能自动解除禁言。

内容操作还需内容可见。例如编辑隐藏帖需要编辑和隐藏查看两项权限，访问内部版块中的匿名作者需要内部访问与作者查询两项权限。移动主题需要主题管理，并满足目标分类的业务发布限制。学习资源的审核与管理使用各自开关，普通内容管理开关不能代替它们。

原生 `moderator` / `staff` 自动组保留在数据库中，但不再隐式赋予管理员分类、搜索、消息和业务发布权限。代码读取有效权限应使用 `guardian.academy_can?(:permission)` 或当前用户的 `academy_moderator_permissions`；判断账号身份应使用存储的 `admin` / `moderator` 属性。不要用 `currentUser.staff` 或有效 `User#staff?` 代替某项能力检查。

## 实现位置

权限注册表、Guardian、查询范围与设置页位于 `plugins/discourse-academy-roles`。受开关约束的管理员只有具备解除禁言权限时，核心审核流程才取消处罚；原生普通分类版主的行为保留，兼容条件明确排除存储身份为 `moderator` 的账号。匿名、严重举报、活动、日历和学习资源功能使用同一能力注册表。

现有线上主题的六个组件作为本次修改基线同步到 `themes/isbf-campus-feed/javascripts/discourse/components`，更新审核入口、日历发布和资源管理按钮。部署只更新这六个数据库主题字段，保留其他字段、主题设置、颜色和当前主题 ID。

学习与官方插件在线上以外部固定版本安装，不属于核心 Git 工作树。它们的改动保存在 `patches/isbf-learning/moderator-permissions.patch` 和 `patches/isbf-official/moderator-permissions.patch`，发布脚本将其合并进新的完整插件发布目录，并校验所有原版本文件哈希。不能原地修改旧发布目录。开发环境需安装相同基线插件再应用补丁；已应用后的完整来源通过发布清单保留。

没有新增数据库迁移。权限值存储于原生站点设置，启动过程不会重置开发者保存的值。

## 验证与部署

部署工具位于 `deploy-work/admin-permissions-20261011`。构建从当前已验证镜像和实际运行容器取基线，检查全部 61 个插件的可见、隐藏文件、内部符号链接及外部发布标记。新镜像仅替换本次权限代码、两个插件的固定发布版本和对应插件的编译资源；保留原有 public assets manifest 条目。

预览使用新建的隔离数据库、合成账号和商品，复用当前主题配置及源代码，不复制生产用户数据。开发者在该预览中实际保存并撤销权限；生产验收使用临时且限源 IP 的只读 API 凭据，验证完成后删除。

部署前保存数据库与上传备份、原主题字段、设置值、原配置和已验证镜像。数据库及上传备份保留在生产服务器的 `/shared/admin-permissions-backups/20261011-<发布提交前12位>` 私有目录（目录权限 `700`，文件权限 `600`），工作区只保存路径、大小与哈希。实际更新采用增量源文件和资源替换，只重启 Web，不替换数据库、Redis 或主题。桌面及手机浏览器验证设置页、工作台、商城、校友及默认关闭的管理员入口后，才更新生产版本配置和 `latest` 已验证镜像。

主题发布脚本将本次 CLI 进程的 `AssetProcessor.timeout` 设为 120 秒，与预览和插件编译一致。完整主题需要编译现有所有 JavaScript 字段，生产默认的 15 秒会在此主题上超时；这不会改变站点设置或其他 Web 请求的超时。

回滚使用原核心版本、原外部插件符号链接、原 manifest 和六个原主题字段，恢复本次调整的站点设置后重启 Web。原已验证镜像作为完整恢复入口。备份和发布清单留在私有部署目录，浏览器验证凭据在验证后删除。

测试覆盖默认拒绝、每个开关单独启用与撤销、开发者兼有管理员身份、普通用户和认证成员、复合审核动作、匿名信息可见范围、内部分类与消息、资料保护、原子保存和设置页实际交互。原生核心回归通过 858 项；最终权限、学习资源、日历和审核回归通过 369 项；设置页 QUnit 交互通过 4 项；连同邀请、登录和学号显示的最终插件页面回归共 31 项全部通过。

官方插件单独运行的 24 项旧测试中有 2 项失败：非法分类与正文同时修订时的回滚，以及 HTTP 元数据编辑持久化。使用原生产插件代码对照复现同样两项失败，属于现有行为，不由本次权限修改引起；其余 22 项通过。该对照记录留在发布目录的 `official-baseline-specs.log`，本次没有修改这些旧事务或 HTTP 编辑行为。

生产后台通知通过同一套 Guardian 评估权限。后台任务由 Pitchfork 的服务进程监督，重载 Web 会同步重载受监督的后台任务。发布脚本仅对确认为同应用、父进程为 `1` 的旧 Sidekiq 先停止接收任务并正常退出，避免脱离监督的旧权限代码继续执行。

首次切换前遇到旧 PID `84164`：任务已正常排空并从 Sidekiq 注册中移除，但 VM 剩余四个线程没有退出。经 PID 启动标识、父进程、剩余线程数和零登记任务核对后，按原生 `Demon::Base#stop` 的超时处理终止残留 VM；受监督的后台进程保留。该次尝试及后续主题超时回滚的备份、配置和校验记录均保留，没有恢复数据库覆盖用户数据。

浏览器验收与发布状态以发布目录的 `preview-browser-report.json`、`production-browser-report.json` 和 `production-report.json` 为准；生产发布报告同时保存在服务器私有部署目录。
