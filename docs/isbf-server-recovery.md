# ISBF 服务器重建前保存与恢复

## 本次保存的范围

2026-10-03 的保存版本提交到学院仓库 `ISBF-Lab/ISBFweb` 的
`feature/isbf-per-post-anonymous` 分支。完整提交在独立代码副本中整理，
当前运行目录及后台主题没有被覆盖。原运行目录的 Git HEAD 和未提交状态因此
不等于此次保存版本；重建时使用交付清单中的提交编号。

保存版本包含学院身份插件、校园主题、核心扩展插槽、测试、设计稿与部署说明。
账户切换、匿名发布、日历、探索、举报管理、通知、转发和浏览统计插件均保存为
仓库内的实际源码目录。运行环境中的容器内软链接没有作为唯一源码保存方式。
转发插件的独立仓库历史另存为备份包中的 Git bundle。

插件清单脚本从 Git 已跟踪的插件入口生成清单，包括已暂存的新插件；提交前的
代码检查可以识别本次新纳入仓库的插件。

原工作区的依赖锁文件与工作区补丁、版本覆盖配置不一致。原始文件保存在私有
备份包中，保存版本采用原 HEAD 的锁文件，并使用项目指定的 pnpm 10.34.5 验证。

## 数据与主题

当前站点运行在 `discourse_dev` 容器中，代码挂载位置为 `/src`，站点数据库为
`discourse_development`。站点备份包含数据库和上传文件；测试数据库不在备份范围。
使用逻辑备份恢复数据库，不复制正在运行的 PostgreSQL 数据目录作为恢复依据。
当前容器的 `USER` 值可能与数据库连接角色不同；原生备份应使用当前已认证连接的
数据库角色，避免 `pg_dump` 误选账号而发生 peer authentication 错误。

默认主题为 ID 4 的 `ISBF Campus Feed`，ID 5 存在同名主题。所有自定义主题及
主题组件分别导出，主题设置、父子关联及默认主题 ID 保存到备份清单中。
仓库主题源码与后台主题是独立副本，两者均予以保存。

备份包包括以下内容：

- Discourse 原生数据库及上传文件备份。
- 自定义主题导出包与运行状态清单。
- 修改前的工作区文件、补丁及全部自定义插件源码快照。
- 转发插件的独立 Git 历史和必要运行配置。
- 完整保存版本的源码归档、检查结果和 SHA-256 校验清单。

真实配置及数据备份不提交到 Git。备份目录和文件限制访问，也不放到公开下载目录。
本次检查备份生成结果、压缩包结构和校验值；按请求未进行恢复演练。

## 检查结果与使用限制

此提交用于保存当前开发状态。依赖冻结安装、静态检查和备份完整性检查已通过；
功能测试已发现失败，完整结果保存在私有备份包的检查记录中。重建完成后仍须
按下文流程核对功能，再恢复正式使用。

## 重建前下载

先将交付的备份包和校验文件复制到另一台机器，再重建服务器。可通过远程编辑器
下载，也可使用已有的 SSH 连接：

```bash
scp codex@8.155.132.213:BACKUP_PATH ./
scp codex@8.155.132.213:CHECKSUM_PATH ./
sha256sum -c CHECKSUM_FILENAME
```

将占位名称替换为交付清单中的实际路径或文件名。保存交付清单中的 Git 提交编号，
以及检查通过、失败或未运行的具体项目。

## 恢复顺序

1. 从学院 fork 获取交付清单中的具体提交，并准备匹配的 Discourse 运行环境。
   当前开发容器镜像与版本信息保存在备份清单中；生产部署方案另行配置。
2. 确认全部自定义插件已加载。在新的目标环境中，通过 Discourse 原生恢复流程
   恢复数据库及上传文件。恢复目标必须与原运行数据库明确区分。
3. 核对站点设置、默认主题、主题组件关联和上传资源。原生数据库备份已保留后台
   主题；单独导出的主题包可用于核对或按需导入，不能盲目覆盖仓库主题修改。
4. 核对邀请注册、官方与普通发布、匿名发布、日历、通知、探索、举报、转发、
   浏览统计和账户切换，再恢复对外入口与后台任务。

`academy_roles:setup` 会重置部分站点设置及分类权限。恢复已有数据库后保留原配置，
只有明确需要重新初始化时才运行该任务。
