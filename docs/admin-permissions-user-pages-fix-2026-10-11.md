# 管理员个人页面加载修复

权限开关调整后，原生个人路由会依次加载用户资料、管理统计和状态。`User.findStaffInfo()` 原先以 `currentUser.staff` 判断是否请求管理统计；这个身份值不能代表“查看用户管理信息”能力。本人资料加载还会将存储的 `moderator` 身份合并进当前用户对象。管理统计接口因缺少具体权限返回 403 后，共用路由将整个个人页面跳转到 `/404`，因此资料、书签、通知、偏好设置和私信都可能受影响。

角色插件在完整用户资料 JSON 中返回 `academy_can_see_staff_info`，值来自访问者的 `Guardian#can_see_staff_info?`。字段为 `false` 时，前端跳过附加统计请求并清除之前加载的统计；请求进行期间权限被撤销而返回 403 时，同样继续打开个人页面。统计接口的其他错误仍返回原有错误，用户资料本身的加载失败保留原有处理。

前端通过插件 API 的 `addModelMethod` 扩展用户模型，前置初始化明确排在 `inject-discourse-objects` 之前，避免当前用户对象先创建而无法应用扩展。字段缺失时委托原方法；角色功能关闭时不输出这个字段，保持原生行为。后端权限、现有 20 项设置值、角色字段、信任等级和用户组成员关系均不调整。

针对性回归覆盖纯管理员全部权限关闭、其他管理权限开启、管理信息独立授权、请求期间撤销、普通用户、开发者、角色功能关闭、旧资料 JSON、真实缺失资料及服务端错误。接口用例同时检查本人书签和通知可访问、他人对应数据继续受保护。前端夹具包含实际序列化中的活动等级、官方成员及本人 `can_edit` 字段，管理统计断言先通过原生按钮展开资料。

前端测试使用 `--target discourse-academy-roles` 配合用例名称筛选；复用构建时，插件源文件路径筛选曾带入旧用例。修改插件测试后，先仅编译角色插件并重启测试 Web，更新测试资源引用。测试库连接池为 2，单进程 Puma 应设置 `PUMA_MIN_THREADS=0`、`PUMA_MAX_THREADS=1`，避免默认 5 个线程耗尽连接池；这些参数仅用于隔离测试环境。

新增 7 个接口用例和 10 个前端用例均已通过。前端首批通过 8 个用例，补齐本人资料的 `can_edit` 夹具后仅运行剩余 2 个；原始两批输出保留在发布资料的 `qunit.log`，`validation.json` 记录去重后的通过用例及两批结果。

增量发布工具位于 `deploy-work/admin-user-pages-fix-20261011`。基线为已上线核心 `67706a5a30d71ff0b6793e5b8f55a85c4fe3ebb5`、镜像 `sha256:e748995d9786f7cac5d0fa1eca66e3c0fafd6765dcd50942d0a88d80ade4345a`。此基线包含权限功能发布后的登录界面布局更新，修复分支已保留这些改动。仅重新编译角色插件，保留全部插件来源、主题、外部插件固定版本和现有 public assets manifest 条目。
