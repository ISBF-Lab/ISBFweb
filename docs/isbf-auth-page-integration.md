# ISBF 登录与邀请码注册页面

以已审核的 V6 全屏粒子原型接入论坛。匿名入口提供「登录」「注册」两个按钮；登录使用论坛原有认证组件，注册使用服务器邀请码与邮箱验证码流程。

## 路由与认证

- `/login` 和要求登录的匿名首页显示双按钮入口。
- `/login?mode=login` 打开密码登录；`/login?mode=code` 保留邮箱验证码入口。
- `/login?mode=register` 和 `/signup` 要求填写邀请码；有效 `/invites/:token` 直接进入邮箱验证。
- 登录保留密码、邮箱验证码、通行密钥及动态配置的社交供应商。新页面设置首页返回地址，验证码登录通过成功回调直接进入首页。
- 注册复用邀请 JSON、`/session/hp.json`、`/session/login-code` 和 `/session/login-code/verify`；邮件限流、必填资料、邀请码单次兑换及学号绑定由原服务器逻辑处理。
- `CodeLoginForm` 的可选 `@onAuthenticated({ accountCreated, redirectUrl })` 在全部认证或资料步骤完成后调用；未提供回调时保留原跳转逻辑。密码重置、错误、双重验证和等待审核不会调用成功回调。

## 页面开关与动效

`academy_auth_page_enabled` 默认关闭，并且仅在 `academy_roles_enabled` 启用时生效。生产发布后启用此开关；关闭可恢复原页面，无需关闭学院权限功能。

字符散开为贴近输入框边界的星云。完成真实注册后表单退场、字符形成对勾、两侧喷出彩带；对勾成形且表单隐藏后开始唯一的 5000ms 截止时间。提示保持「5 秒后进入论坛首页」，进度环读同一截止时间。暂停动效不暂停跳转；退出页面清理动画、监听、观察器及计时。

动效复用已审核原型的字符图集、30fps 上限、桌面 6800／触屏或窄屏 3000 字符及 DPR 上限。颜色读取论坛 CSS 变量，主题切换使用原有 InterfaceColorSelector。系统减少动态效果及 Canvas 不可用时保留表单、成功状态和跳转。独立预览中的演示账号、验证码及请求模拟均不接入正式页面。

## 对齐、标识及触控

认证面板内各步骤使用完整宽度与居中排版，验证码格单独整体居中。通用输入样式排除原生 `DOtp` 的透明输入层，避免破坏验证码命中区域、粘贴与自动填充。关闭按钮位于面板内部，距顶端及行尾各 16px，点击区域 44px，面板顶部预留 72px。

左上角名称读取论坛 `title`，图标优先使用 `site_logo_small_url`，缺失时使用 `site_logo_url`；沿用首页 Logo 的默认深色方案及 URL 转换规则，并由原生 Logo 组件处理明暗模式切换。没有图片时仅显示名称。中央已审核的粒子造型独立于页头标识。

粒子交互限定在认证页面背景：鼠标移动产生斥力，触屏或触笔点按立即产生同类反馈，拖动跟随当前位置，释放后衰减回拢。背景使用 `touch-action: pinch-zoom`，阻止单指拖动触发页面滚动，并保留双指缩放；欢迎区空白透传事件，按钮和表单正常接收操作。触屏拖动捕获到背景区域，跨过表单边缘仍保持反馈；松手释放捕获，取消、丢失捕获、切换场景、暂停或离开页面清理状态。Canvas 不可用时继续使用静态回退。

认证页普通文字禁止选择及长按浮层，输入框、文本域和可编辑区域显式恢复选择与编辑菜单。表单仍可滚动，滚动链限制在认证页。手势限制仅作用于背景，不能放到表单共同祖先上，否则移动端表单滚动和输入框编辑会受影响。验收须包含超过浏览器滑动阈值的实际触控拖动和长按，仅点按或短距离移动不足以证明手势不会被浏览器接管。

## 验证与发布

接入测试集中覆盖入口、真实认证组件、邀请码 JSON 错误、既有学号绑定和邮箱激活流程、成功计时及页面开关；不重复执行完整的原型动效测试。发布基于实际生产提交建立独立版本，保存旧镜像、配置和原生数据库／上传备份。

本次不增加数据库迁移、依赖或 OAuth 配置。发布结果、检查记录及可下载源码包另见本次发布记录。

## 已注册邮箱的验证码提示

邀请码仅用于创建新账号。已注册邮箱输入有效验证码后，兑换流程应返回「此邮箱已注册，请返回登录页面登录」，不应将重复注册误报为验证码错误或过期。学院兑换器使用 `Invite::UserExists` 表达已存在的账号，让原生验证码控制器返回可读原因；验证码及邀请码的事务回滚保持原有行为。未通过验证码验证时仍返回通用验证码错误，避免暴露账号状态。正常登录可以使用拒绝重复注册时尚未消费的有效验证码。

## 认证页字段居中与主题菜单维护（2026-10-11）

邀请码字段通过 FormKit 的 `@format="full"` 铺满表单，认证页专用字段类恢复
子元素拉伸，使标签、输入框和框内文字共享表单中线。使用字段类及 `data-name`
定位，避免依赖生成的 Ember ID 或子元素序号。

原生密码字段标签在认证页移到输入框上方，因此小眼睛不能继续按整个字段组的
顶部定位。认证页字段组改用网格：标签在第一行，输入框和小眼睛在第二行，
辅助链接仍在后续行；按钮靠行尾并沿输入框垂直居中。按钮最小点击宽度为 44px，
输入框两侧内边距相等，显示或隐藏密码均保持文字居中。
标签元素使用 `justify-self: center` 沿网格中线放置，避免标签元素自身偏离中线。
基础标签样式使用 Flex，因此同时设置 `justify-content: center`，确保标签内
实际文字也居中；只核对标签外框和 `text-align` 不能证明可见文字已居中。

原生主题菜单通过 portal 挂载在页面根部，其默认层级低于全屏认证页。仅在
`body.academy-auth-page` 下，将 `interface-color-selector` 菜单提升到
`fullscreen + 1`，仍低于原生弹窗；其他页面的菜单层级保持原值。浅色、深色及
跟随系统继续由原生 InterfaceColor 服务管理，刷新和进入论坛时沿用所选模式。
