# 学号邀请码使用说明

学院插件启用（`academy_roles_enabled=true`）后，每个注册邀请码必须绑定一个学号，
并且只能用于注册一个新账号。注册成功时，服务器自动将学号绑定到该账号。
只有站点管理员能查看学号；版主、普通成员、匿名身份和访客都不能查看，包括账号本人。

## 管理员发码

1. 使用站点管理员账号登录，打开
   `/admin/plugins/discourse-academy-roles/student-invites`，点击“生成学号邀请码”。
   `/new-invite` 和个人邀请页面的创建按钮也会打开同一个学号发码表单。
2. 输入学号和有效天数。学号按字符串保存，去除首尾空白，最多 64 个字符，
   保留前导零；例如 `001234` 和 `1234` 是不同学号。有效期默认采用
   `invite_expiry_days`，可选范围为 1–36500 天。
3. 创建后复制邀请码或完整邀请链接，发给对应学生。邀请码自动限制为单次使用，
   不预先绑定邮箱，也不授予官方成员身份。

同一个学号不能重复发码。对于尚未注册的学号，在列表中点击“重新生成邀请码”
即可发新码，旧码立即失效；也可以撤销未使用的邀请码。已过期、已撤销或已删除的
邀请仍保留学号记录，重新发码应使用原记录的“重新生成邀请码”。

### CSV 批量发码

在学号邀请码后台点击“CSV 批量生成邀请码”，也可直接打开
`/admin/plugins/discourse-academy-roles/student-invites/bulk`。

1. 下载 CSV 模板，替换其中的示例学号。文件使用 UTF-8 编码，每行一个学号；
   表头可为 `student_number` 或“学号”，也可以不带表头。每批最多 1500 行数据，
   文件不能超过 1 MB。学号按字符串保存，保留前导零；在 Excel 中编辑或导入时，
   将学号列设为文本，避免在保存 CSV 前丢失前导零。
2. 上传文件并设置统一有效天数，点击“生成并下载 CSV”。已有学号全部跳过，
   包括未兑换、已注册、已过期和已撤销的记录，不导出旧码、不更换原码。
   文件内重复学号也跳过。空学号、超过 64 字符或含多列的行标为失败，其他行继续。
   格式损坏、编码错误、空文件或超限会在生成前拒绝整批文件。
3. 下载的结果按输入顺序列出学号、邀请码、邀请链接、到期时间（UTC）、处理结果和原因。
   只有新生成的行包含邀请码及链接；跳过和失败行的对应列留空。
   文件采用带 BOM 的 UTF-8 编码，可直接用于分发。
4. 页面显示生成、跳过、失败数量，并支持“再次下载结果 CSV”。结果仅保存在本次
   页面中，离开或刷新前请保存文件；重复导入会按已有学号全部跳过处理。

批量上传使用管理员专用 `POST /academy-roles/admin/student-invites/bulk`，
返回计数及结果 CSV；有新码时为 `201`，全部跳过或失败时为 `200`，文件级错误为 `400`。
后台先完整解析文件、批量查询已有学号，再通过原有发码服务逐行事务处理。
单行失败会回滚其邀请码和学号记录，并发冲突会跳过已保留的学号。
文件不写入公开附件，导出对 CSV 引号及电子表格公式进行安全处理；每个新码仍只允许
注册一个新账号，学号可见权限沿用站点管理员限制。

## 学生注册

1. 在登录页输入邀请码，或直接打开管理员发来的邀请链接。
2. 填写邮箱、用户名、密码等注册信息。页面不显示学号，也不要求学生手动填写学号。
   密码注册和邮箱验证码注册均使用服务器保存的学号绑定。
3. 注册成功后，该学号与新账号永久绑定，邀请码不能再次使用。已有正式账号不能
   使用邀请码添加或更换学号。

注册失败会回滚账号创建、邀请码兑换次数和学号绑定，不会消耗邀请码。
单纯打开链接也不会消耗邀请码。并发注册时，同一邀请码最多有一次兑换成功。

邮箱激活仍沿用 Discourse 核心流程。密码注册后可能需要邮箱验证；学院初始化关闭的
“管理员审批”与邮箱激活是两个独立步骤。生产站点若仍未配置发信，需要完成 SMTP
配置或由管理员手动激活账号；本功能不跳过邮箱验证。

### 尚未配置邮件时注册与激活

邮箱验证码页面的“已发送”表示发送任务已提交，不代表邮件已成功投递。
未配置 SMTP 或 `disable_emails=yes` 时，用户无法通过验证码继续注册；
此时账号尚未创建，后台也没有可激活的账号。申请验证码不会消耗邀请码。

暂时不用邮件时，关闭 `enable_local_logins_via_code`，保持
`enable_local_logins=true`，让学生重新打开原邀请链接，填写邮箱、用户名和密码
提交注册。该开关也会将本地登录切换回密码登录。

管理员激活步骤：

1. 用管理员账号打开 `/admin/users/list/new`，搜索学生注册时填写的用户名或邮箱。
   可将“激活状态”筛选为“未激活”。
2. 打开该用户详情，在“已激活”一栏点击“激活帐户”。
3. 确认状态变为“是”，学生即可用用户名或邮箱及密码登录。

“发送激活电子邮件”依赖发信配置，不能替代手动激活。“批准用户”也不能替代
邮箱激活。管理员应先核对学生身份及邮箱；手动激活表示管理员确认该账号可以使用。

### 配置邮件后恢复验证码注册

确认运行中的生产容器已加载 SMTP，且 `disable_emails=no`，再开启
`enable_local_logins_via_code`；本地登录和本地邮箱登录也须启用。
注册用户需刷新并重新打开邀请链接，申请新的验证码。
邀请码兑换及验证码验证成功后，账号会完成邮箱激活，无需管理员手动激活。

管理员可在后台自行切换验证码注册：

1. 打开 `/admin/config/upcoming-changes`（“即将推出的更改”），搜索
   `enable_local_logins_via_code`。也可直接打开
   `/admin/config/upcoming-changes?changeNamesFilter=enable_local_logins_via_code`。
2. 将该项目右侧“已启用…”的下拉框设为“所有人”以开启，设为“没有人”以关闭。
   选择后自动保存，无需重启服务器。
3. 注册用户刷新并重新打开邀请链接，使用新的注册流程。

这个开关同时控制验证码注册、接受邀请和验证码登录；关闭后使用密码流程，
密码注册仍需邮箱激活或管理员手动激活。是否必须持有邀请码由 `invite_only` 控制。

## 管理员查看绑定

邀请码列表显示学号、状态和已注册账号，可点击账号进入管理员用户详情。
管理员用户详情中的“学号”是只读字段。旧账号未补绑学号，显示“未绑定学号”。

注册后的学号不能修改、重发或转移；删除邀请码或账号也不会释放该学号。
删除账号后，邀请码列表保留“已注册”记录，账号列不再提供账号链接。
任何一方已经绑定学号的账号合并操作都会被拒绝。匿名身份不会获得学号绑定。

学号保存在独立的 `academy_student_registrations` 表中，不使用公开用户自定义字段。
只有管理员专用接口和管理员用户序列化器返回学号；公开资料、当前用户、偏好设置、
邀请兑换页面及版主用户详情接口均不返回该字段。

### 运维补绑原有账号

现有界面没有给旧账号补填学号的按钮。站点负责人提供明确的账号和学号后，
运维可以在生产后台执行一次绑定，不需要让用户重新注册或更改数据库结构。

1. 按用户名定位正式账号，排除系统、暂存和匿名身份，并核对账号及学号均未绑定。
2. 在同一个数据库事务中锁定目标账号，通过既有 `CreateStudentInvite` 服务
   创建学号记录；使用系统管理员身份并保留 `skip_email: true`。
3. 将该记录关联的邀请设为失效，再用模型的 `update!` 写入现有账号及
   `registered_at`。现有表要求 `invite_id` 非空，所以需保留这条无法兑换的
   邀请记录；它仅用于支撑补绑，不发送给用户。
4. 核对绑定、邀请不可兑换以及管理员详情能显示学号，再提交事务。
   重复执行时，只有完全相同的账号与学号绑定可视为已完成；出现任何冲突即停止。

补绑沿用既有唯一性、不可更改、删除保留、合并限制及管理员可见规则。
具体账号与学号的对应关系保留在受保护的管理数据中，不写入仓库文档。

## 升级已有站点

部署代码并执行数据库迁移后，重启 Web 和后台任务进程。插件启用时，旧的未绑定
学号邀请码会被服务器拒绝兑换，已有账号保持可用。

可再运行下列任务，让旧码在核心邀请列表中也明确显示为失效：

```bash
LOAD_PLUGINS=1 bin/rake academy_roles:invalidate_unbound_invites
```

此任务只更新无学号记录的邀请码失效时间，可重复执行；不会删除邀请码或账号。
它要求学院插件已启用。无需重新运行 `academy_roles:setup`，该初始化任务会重设
站点设置及分类权限。
