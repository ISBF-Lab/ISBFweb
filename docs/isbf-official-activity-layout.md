# 官方活动四格布局

官方消息列表按作者与标题、正文、活动信息、互动按钮的顺序显示。每个活动有独立标题及两列两行信息：活动时间、报名截止时间、地点、主办方。桌面和手机保持两列，长文字换行，配色跟随明暗主题。

没有报名截止的活动显示“无”，未填写地点或主办方显示“未填写”。普通公告不显示活动信息。独立截止日期显示名称和时间；历史活动与历史截止项不会自动关联。

编辑器提供活动和独立截止日期两种时间项。活动可选填地点、主办方及自己的报名截止；一条消息可包含多个活动。报名截止仍保存为可单独导入个人日历的时间项。地点、主办方和关联保存在消息修订记录中，个人日历快照及时间变更通知维持原有语义。

## 实现与验证

后端为 `isbf-calendar` 0.3.0，迁移 `20261006160545_add_official_activity_details.rb` 增加两个文本字段及截止关联。请求仍使用平面数组，通过 `registration_deadline_index` 连接活动和截止项；响应使用持久 ID。详情见插件 README。

主题新增 `isbf-official-activity-summary`，官方分类的通用列表与专用官方列表都使用四格布局。布局依据主题配置的官方分类路径判定，最新消息流和话题详情保持现有摘要与添加日历按钮。编辑器和时间转换助手负责在活动分组与平面数组之间转换，保留已有时间项 ID 和版本。

实现前源码快照、隔离主题备份、增量字段清单及验收产物保存于 `deploy-work/official-activity-layout-20261007/`。后端 165 项 RSpec 用例通过，覆盖字段校验、关联与取消、旧客户端、权限、修订记录及个人日历兼容。

主题 QUnit 58 项测试、195 个断言全部通过，包括两个活动的不同报名截止、截止精度切换、字段占位、转义和原有日历及标题校验。变更文件通过 ESLint、Prettier、Stylelint、Syntax Tree 和 RuboCop。迁移后的 `db:dump_structure` 未改变核心结构文件；模型注释已生成。条件写法调整后，保存服务的 39 项测试再次通过。

官方分类路径兼容修复后，活动转换与路由模块的 6 项测试、31 个断言再次通过。开发实站实际保存了两个活动、各自的报名截止及一个独立截止项，关联和时间精度正确；桌面和手机的明暗模式均保持两列，顺序正确，无横向溢出或页面脚本错误。验证消息随后删除，时间源标记取消。

隔离开发数据库必须使用 `DISCOURSE_DEV_DB`；`RAILS_DB` 只选择测试环境数据库。测试工具的 Chromium 需要 `DISCOURSE_DISABLE_BROWSER_SANDBOX=1`。低内存环境可直接用 Playwright 加载 `/theme-qunit?id=ID` 并收集 QUnit 回调；Pitchfork 编译请求可能需要增大 `UNICORN_TIMEOUT`，也可使用现有 Puma 服务器。独立测试服务器设置 `CI=1` 可关闭针对核心主题目录的开发监听，避免将自定义主题误当作核心主题同步。

## 发布与回退

先导出当前默认主题，逐字段合并本次源码补丁并校验哈希；保留其他主题字段、设置和组件。部署顺序为原生数据库与上传备份、后端固定提交重建和新增迁移、主题增量同步、实站验收、解除维护锁。

回退主题只恢复本次涉及的字段。代码回退使用发布前保留镜像和完整配置。新增数据库字段保持兼容，回退不删除它们，也不恢复可能覆盖用户新写入数据的旧数据库备份。
